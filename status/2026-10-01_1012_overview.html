What this is and why

mozaic is the Python library that produces Mozilla's Firefox daily-active-user (DAU) forecasts. It forecasts daily DAU for desktop and for mobile through the end of the year, and a cycle is judged on one number per platform: the 28-day average on December 15. The library first runs a holiday corrector over each series (it estimates what each day would have been without the holiday and replaces the dip), then fits one Prophet model per country and user segment (new profiles versus everyone else), plus one per country, one per segment, and one for the world. Reconciliation then adjusts the small forecasts so they sum to the large ones. A separate pipeline, mozaic-daily, pulls telemetry from BigQuery, calls this library, and publishes the monthly forecast cycle that the KPI sheet and executive updates read. Brad owns the mozaic library; Brendan Wells is a frequent contributor to it and owns mozaic-daily. Brendan works in each repository with a Claude Code agent. Below, "the pipeline agent" is the agent in the pipeline repository; it asks this library for features, and the handoff memos are notes between the two agents.

Until March 2026 every model setting was hard-coded, and the library could not handle a country whose telemetry vanished. Over the following months each forecast cycle raised a new need and this branch absorbed it: first the desktop model had to be tunable so that its forecast for late August matched the summer trough, then Iran's internet was shut off for 87 days, leaving a crater that Prophet reads as a real trend. In a validation run with data through late June, a month after service was restored, the unfilled model still forecast Iran desktop DAU falling to about a tenth of its level by year-end. Iran matters: it is Firefox's fifth-largest mobile market, and on desktop roughly 1M of about 50M DAU. The changes were accumulated over several cycles rather than designed together, and they are meant to be temporary. The August and September 2026 forecast cycles were built with them.

Where it stands

Every capability the cycles asked for is built and in use. The published August and September forecasts were produced by hand on a local checkout of this branch; the automated scheduled job still runs March code from main and does not have these capabilities. How far the scheduled job's output differs from the hand-built forecast is not recorded anywhere. The branch has not been merged to main and no pull request exists, by choice: the changes are hoped to be temporary, and merging would require a formal code review that there has not been time for. Meanwhile main has gained a holiday-corrector bug fix that this branch lacks. Nothing was committed here between 2026-07-29 and this document's date; the two cycles in between were pipeline-side work.

On forecast quality, the record is thin. The pipeline's own sweep notes that forcing the scaling-with-level regime recovered about seventy percent of the gap to its late-August desktop target, which is why that setting was adopted. Whether the resulting September forecast was more accurate than the old model's is not evaluated anywhere in this repository.

How it works
  • One config object per platform. A dataclass holds every tunable setting for desktop or mobile, with defaults equal to the old hard-coded values, so a default run is identical to the pre-branch library.
  • Configs are plain objects the pipeline can vary and compare. Existing callers keep working unchanged, and each config has a short label so sweep outputs stay distinguishable.
  • Seasonality regime is a dial, not just a switch. The desktop model used to pick additive or multiplicative seasonality per series from a hidden correlation test; the branch exposes that test's threshold as a continuous dial, plus a way to force either regime outright.
  • The Iran gap is filled with a counterfactual, not masked. The package ships a pre-computed "what Iran would have done" series and splices it over the shutdown window as data loads, the way it applies a country's holiday calendar.
  • The model trains on the fill but reports the truth. Each series keeps its real history for reporting actuals and a separate fit history that carries the synthetic values; only the fit history reaches Prophet.
  • Holidays can be switched off for one country in one year. The skipped dates leave that country's calendar for that year only, so every part of the library treats them as ordinary days; every other year is untouched.
  • Loud warnings instead of silent no-ops. The library warns when it clips a holiday effect or when a fill finds no rows for its country.

Record of work

Chronological, one short paragraph per stage. Reconstructed from commit history, code comments, and research notes.

April forecast model changes

2026-03-24 to 2026-04-07 · commits 82aa9ee through 9ffb585

The desktop model gained yearly seasonality and both platforms gained conditional weekly seasonality (a recent weekly pattern projected forward, an older one kept for fitting). Logistic cap and floor moved to a trailing window. A warning now fires when a holiday effect would be clipped at the floor. A mobile-specific event calendar recorded an organic DAU loss from mid-February to early March 2026. Metaparameters were retuned for the April cycle.

Configurable model

2026-05-13 to 2026-05-26 · commits 7db8ec7 through aa40756

Introduced the config dataclass hierarchy and factory functions, with every default equal to the prior hard-coded value. Exposed the holiday detrender settings and the holiday effect floor, then the changepoint range and count. Widened the cap window to 426 days. Added the README, an architecture doc, and a module index. The governing decision (D-001) was that a default run must stay identical to the old library.

Iran shutdown: investigation, pivot, and shipped fill

2026-06-26 to 2026-06-30 · commits 3221fff through 97c971c

First tried masking the 87-day gap as a single long holiday. Validation on real data showed desktop interpolated cleanly but mobile's weekly shape fell apart, because the detrender's recurrence is only marginally stable. Pivoted to a synthetic counterfactual generated by the pipeline from pre-shutdown history (D-002: splice a counterfactual instead of masking). The library gained a splice operation, a real-versus-fit split of each tile's history (D-003: train on the fill, report real actuals), and a fills registry shipping the Iran parquets as package data and applying them automatically (D-004: a fill belongs to the country like its holiday calendar). Two follow-up fixes from the pipeline team: a date-type mismatch that blanked every tile, and a warning when the fill's country had been bucketed into ROW. Labour Day and Whit Monday were added to the global calendar. Validation data was pulled from Glean; the production run uses Legacy.

Per-country-year holiday skips

2026-07-02 · commit 0883806

After the January blackout, the detrender's expected level floated about 16 percent above Iranian actuals through February, and holidays inside the filled gap fired corrections on top of the synthetic values. Several broad fixes were tried and rejected because they moved every country (D-005: skip per country-year, not globally). The accepted mechanism skips named holidays for one country-year only; a blast-radius script confirmed no other country changed. Fourteen 2026 Iranian holidays are skipped.

Seasonality knobs for the pipeline's parameter search

2026-07-10 to 2026-07-29 · commits 126fe14 through 4f33650

At the pipeline team's request, exposed the seasonality prior scale, then a regime enum that can force additive or multiplicative seasonality (D-006: on desktop the regime also fixes the growth type, to stay in tested territory), then a continuous correlation threshold for the desktop auto-switch (D-007: desktop only, rejected with an error on mobile). Shipped four scripts: a diagnostic of how the auto-switch resolves across tiles, a behavioural check that the enum reaches Prophet, a full-tile robustness run under each forced regime, and the holiday-skip blast-radius check. Fixed the slug to include holiday radii, which had been silently overwriting sweep outputs.
